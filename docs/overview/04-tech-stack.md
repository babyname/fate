# fate 技术栈选型

## 技术栈总览

fate 采用以下技术栈：

| 技术 | 版本 | 用途 | 说明 |
|-----|------|------|------|
| Go | 1.25.0+ | 主语言 | 性能好、并发强、编译快 |
| chronos/v2 | v2.0.7+ | 八字计算库 | 封装 lunar-go，提供 FateData |
| yi | v1.0.2+ | 周易数据 | 六十四卦数据 |
| sqlite3ent/sqlite3 | v1.50.0+ | SQLite 驱动 | 纯 Go，CGO_ENABLED=0 |
| YAML/JSON | 1.2 | 配置文件 | 配置参数管理 |
| Go testing | 内置 | 测试工具 | 单元测试、集成测试 |

---

## Go语言选型

### 为什么选择Go？

**优势**：

1. **性能优秀**：
   - 编译速度快
   - 运行效率高（接近C）
   - 内存占用低
   
2. **并发强大**：
   - goroutine轻量级并发
   - channel通信机制
   - 适合批量处理
   
3. **开发高效**：
   - 语法简洁
   - 编译速度快
   - 工具链完善
   
4. **部署简单**：
   - 编译为单一可执行文件
   - 跨平台支持
   - 无运行时依赖
   
5. **社区活跃**：
   - 丰富的第三方库
   - 活跃的社区支持
   - 完善的文档

### Go 在 fate 中的应用

| 应用场景 | Go优势 | 说明 |
|---------|-------|------|
| 八字计算 | 性能高 | 快速计算，响应时间 < 1秒 |
| 批量处理 | 并发强 | goroutine批量处理，高效 |
| API服务 | 并发强 | 高并发API服务 |
| 跨平台部署 | 编译简单 | Windows/Linux/macOS一键部署 |

### Go 版本要求

- **最低版本**：Go 1.21
- **推荐版本**：Go 1.22+

**原因**：
- Go 1.21 提供了更好的性能优化
- Go 1.21 提供了更好的错误处理
- Go 1.21 提供了更好的泛型支持（可选）

## lunar-go 选型

### 为什么桥接 lunar-go？

**优势**：

1. **功能完整**：
   - 提供所有起名需要的功能（八字、纳音、五行、十神、藏干等）
   - 使用天文算法计算节气（精确）
   - 支持多流派（立春修正、早子时/晚子时）
   
2. **维护良好**：
   - 活跃维护（持续更新）
   - 跨语言支持（Java、Go、Python等）
   - 社区支持
   
3. **零依赖**：
   - 无外部依赖
   - 自包含数据表
   - 简化部署
   
4. **准确可靠**：
   - 使用天文算法（精确）
   - 数据范围广（1900-2100+）
   - 测试完善

### lunar-go 版本要求

- **最低版本**：v1.3.0
- **推荐版本**：v1.3.0+

**原因**：
- v1.3.0 提供了完整的功能
- v1.3.0 提供了多流派支持
- v1.3.0 稳定可靠

### lunar-go 在 fate 中的应用

| 应用场景 | lunar-go功能 | 说明 |
|---------|-------------|------|
| 公历转农历 | Lunar | 公历转农历日期 |
| 八字计算 | EightChar | 计算四柱干支 |
| 纳音、五行、十神 | EightChar | 计算纳音、五行、十神、藏干 |
| 大运计算 | Yun | 计算大运、流年、流月 |
| 节气计算 | Solar | 精确节气时刻 |

### lunar-go 的不足

**不足之处**：
- lunar-go 不提供五行喜忌分析（fate 自己实现）
- lunar-go 输出格式复杂（fate 简化输出）
- lunar-go API 不友好（fate 优化API）

**解决方案**：
- fate 自己实现五行喜忌分析
- fate 使用桥接模式简化输出
- fate 提供优化的FateAPI

## 数据库选型

### 为什么选择 SQLite/MySQL？

**SQLite 优势**：

1. **轻量级**：
   - 无需安装数据库服务器
   - 单文件数据库
   - 部署简单
   
2. **性能足够**：
   - 适合中小规模数据
   - 适合单机应用
   - 读性能好
   
3. **零配置**：
   - 无需配置
   - 无需维护
   - 简化部署
   
4. **跨平台**：
   - 支持Windows/Linux/macOS
   - 无平台依赖

**MySQL 优势**：

1. **高性能**：
   - 适合大规模数据
   - 适合高并发
   - 读性能好
   
2. **功能强大**：
   - 支持复杂查询
   - 支持索引优化
   - 支持事务
   
3. **可扩展**：
   - 支持集群
   - 支持分布式
   - 适合企业应用

### 数据库在 fate 中的应用

| 应用场景 | SQLite适用 | MySQL适用 | 说明 |
|---------|-----------|---------|------|
| 单机应用 | ✓ | ✗ | SQLite适合单机应用 |
| 企业应用 | ✗ | ✓ | MySQL适合企业应用 |
| API服务 | ✗ | ✓ | MySQL适合API服务（高并发） |
| 汉字数据库 | ✓ | ✓ | SQLite/MySQL都适合 |

### 数据库选择建议

**单机应用**：使用 SQLite
- 部署简单
- 无需维护
- 性能足够

**企业应用/API服务**：使用 MySQL
- 高并发支持
- 可扩展
- 企业级功能

### 数据库版本要求

- **SQLite**：3.x+
- **MySQL**：8.x+

## 技术栈对比

### 与其他语言的对比

| 技术栈 | 优势 | 劣势 | 适用性 |
|-------|------|------|-------|
| **Go + lunar-go** | 性能好、并发强、部署简单 | 社区相对较小 | ✓ 最适合 |
| Java + lunar-java | 社区大、生态完善 | 性能略慢、部署复杂 | ✗ 可选 |
| Python + lunar-python | 易用、生态完善 | 性能慢、并发弱 | ✗ 不适合 |
| Node.js | 易用、并发强 | 性能中等 | ✗ 不适合 |

### 结论

**Go + lunar-go 最适合 fate**：
- 性能优秀（响应时间 < 1秒）
- 并发强大（批量处理高效）
- 部署简单（单一可执行文件）
- 功能完整（lunar-go提供所有功能）

## 技术风险和应对

### 技术风险

| 风险 | 影响 | 应对策略 |
|-----|------|---------|
| lunar-go 版本更新 | API变化 | 版本锁定、桥接模式隔离 |
| Go 版本更新 | 语法变化 | 版本锁定、兼容性测试 |
| 数据库性能瓶颈 | 批量处理慢 | 索引优化、缓存优化 |
| 配置文件解析错误 | 启动失败 | 验证逻辑、默认配置 |

### 应对策略

1. **版本锁定**：
   - go.mod锁定依赖版本
   - 避免意外升级
   
2. **桥接模式隔离**：
   - 使用桥接模式隔离lunar-go
   - 避免API变化影响
   
3. **索引优化**：
   - 数据库索引优化
   - 提升查询性能
   
4. **缓存优化**：
   - 缓存常用数据
   - 减少数据库查询
   
5. **验证逻辑**：
   - 配置文件验证
   - 默认配置兜底

## 技术栈总结

### 核心技术栈

| 技术 | 版本 | 用途 | 必选/可选 |
|-----|------|------|----------|
| Go | 1.21+ | 主语言 | ✓ 必选 |
| lunar-go | v1.3.0+ | 农历库 | ✓ 必选 |
| SQLite | 3.x+ | 数据库（单机） | ✗ 可选（单机） |
| MySQL | 8.x+ | 数据库（企业） | ✗ 可选（企业） |
| YAML | 1.2 | 配置文件 | ✓ 必选 |
| Go testing | 内置 | 测试工具 | ✓ 必选 |

### 技术栈优势

1. **性能优秀**：Go + lunar-go 响应时间 < 1秒
2. **并发强大**：goroutine 批量处理高效
3. **部署简单**：单一可执行文件 + SQLite
4. **功能完整**：lunar-go 提供所有功能
5. **易于维护**：桥接模式隔离、版本锁定

### 技术栈劣势

1. **Go社区相对较小**：不如Java/Python社区大
2. **lunar-go不提供五行喜忌**：需要自己实现
3. **数据库性能瓶颈**：大规模数据需要MySQL

---

## 总结

fate 采用 Go + lunar-go + SQLite/MySQL + YAML/JSON 技术栈，兼顾性能、并发、部署、功能、维护等因素，是起名工具的最佳技术选择。

**核心优势**：性能优秀、并发强大、部署简单、功能完整、易于维护
